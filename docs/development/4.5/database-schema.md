# SolarInspector 4.5 database schema

## Status and decision

Schema version 1 represents the explicitly recorded, characterized Phase 09
baseline. Schema version 2 adds normalized measurement and source-selection
time series. The existing five domain tables remain authoritative for current
compatibility behavior:

- `samples`;
- `phase_samples`;
- `grid_meter_samples`;
- `validation_events`;
- `energy_balance_samples`.

`measurements` is authoritative for accepted normalized time-series values
after migration to version 2. `source_selection_events` is authoritative for
new Phase 09 source decisions. `schema_migrations` and `migration_findings`
provide migration audit data.

Their complete inventory, units, NULL behavior, keys, and compatibility
findings are documented in
[`phase-10-schema-inventory.md`](phase-10-schema-inventory.md).

The durable target decision is additive consolidation:

1. retain `samples` as the compatibility parent until dashboard, API, and CSV
   reads have an explicit migration path;
2. version every subsequent schema change;
3. add normalized time-series storage only when its writer and migration are
   implemented in blocks 10.4–10.6;
4. avoid copying legacy values whose source, unit, timestamp, or quality is
   ambiguous;
5. preserve the Phase 05–09 detail tables instead of adding equivalent
   parallel tables.

This keeps Phase 09 behavior backward-compatible while allowing later Phase
10 schema versions to introduce normalized measurements, migration findings,
and source-selection history with a documented transition.

## Schema-version ledger

### `schema_migrations`

One immutable row records each committed forward migration.

| Column | Type | Meaning and constraints | NULL/default | Origin and migration behavior |
| --- | --- | --- | --- | --- |
| `version` | `INTEGER` | Positive, contiguous application schema version; primary key | Not NULL through primary key; no default | Defined by application migration; never reused |
| `applied_at` | `TEXT` | UTC ISO-8601 timestamp with offset | Not NULL; no default | Supplied by migrator clock and normalized to UTC |
| `description` | `TEXT` | Stable human-readable migration purpose | Not NULL; no default | Must match the compiled migration definition |
| `application_version` | `TEXT` | Application version that performed the migration | Not NULL; no default | Supplied by migration caller; audit information only |
| `checksum` | `TEXT` | Lowercase SHA-256 migration-definition digest | Not NULL; no default | Must match the compiled migration definition |

The table contains no physical measurement units. It has no foreign keys,
secondary indexes, JSON, or sensitive device data. The integer primary key is
the lookup and ordering index; another index would be redundant.

### `migration_findings`

This table records ambiguity without changing or discarding the source value.

| Column | Type | Meaning and constraints | NULL/default | Origin and migration behavior |
| --- | --- | --- | --- | --- |
| `id` | `INTEGER` | Finding identifier and primary key | Not NULL through primary key | Generated by SQLite |
| `migration_version` | `INTEGER` | Migration that observed the condition | Not NULL; no default | Compiled migration version; dimensionless |
| `finding_code` | `TEXT` | Stable diagnostic code | Not NULL; no default | Migrator |
| `severity` | `TEXT` | `warning` or future documented severity | Not NULL; no default | Migrator |
| `table_name` | `TEXT` | Source table, when applicable | Nullable; no default | Schema inspection |
| `column_name` | `TEXT` | Source column, when applicable | Nullable; no default | Schema inspection |
| `source_row_id` | `INTEGER` | Preserved source-row identifier, when applicable | Nullable; no default | Legacy primary key; dimensionless |
| `details_json` | `TEXT` | Bounded non-sensitive action metadata | Not NULL; default `{}` | Migrator; valid JSON object |
| `created_at` | `TEXT` | UTC ISO-8601 migration timestamp with offset | Not NULL; no default | Same clock as ledger row |

`idx_migration_findings_version_code(migration_version, finding_code)` supports
post-migration diagnosis by run and condition. Findings do not reference
domain rows with a foreign key because the source table may be unknown or may
be transformed by a later migration.

## Version 1 migration

Version 1 is named “Migrate known unversioned schemas to the Phase 09
baseline.”

- Supported sources: the characterized 48-column 4.1.3 `samples` schema, its
  older 21-column “v3-style” base, and additive Phase 05–09 shapes.
- Changes: create the audit tables; add missing Phase 05–09 columns as
  nullable; create missing detail tables and indexes; record version 1.
- Transaction: `BEGIN IMMEDIATE`, DDL, ledger insert, full verification,
  commit.
- Rollback: any SQL or verification failure removes the new table and ledger
  row.
- Data loss: none; source tables, rows, columns, and values are preserved.
- NULL and zero handling: original fields remain unchanged. Missing later
  fields are added as nullable and therefore become `NULL`, not zero.
- Unknown extra columns: preserved in place and recorded as findings.
- Uninterpretable local timestamps: preserved unchanged and recorded as
  findings; epoch timestamps are not rewritten.
- Missing required 4.1.x columns: rejected and rolled back.
- Newer schemas: rejected without a migration attempt.

The application does not invoke this migration automatically in block 10.2.
Backup creation, dry run, CLI integration, and startup policy are later
mandatory blocks. This prevents an audit-table write from bypassing the
required operational safeguards.

## Version 2 migration

Version 2 is named “Add normalized measurements and source-selection events.”

- Supported source: verified schema version 1.
- Change: create `measurements`, `source_selection_events`, and three indexes.
- Transaction and rollback: shared with the ordered migration transaction.
- Historical backfill: none. Version 2 does not infer source, quality, unit, or
  timestamp for existing wide rows.
- Data loss: none.

### `measurements`

One row stores one accepted normalized value for one collector cycle.

| Column | Type | Meaning and unit | NULL/default | Origin and migration behavior |
| --- | --- | --- | --- | --- |
| `id` | `INTEGER` | Row identifier | Primary key; generated | SQLite |
| `sample_id` | `INTEGER` | Parent collector cycle | Not NULL; no default | `samples.id`; cascade delete |
| `source_id` | `TEXT` | Stable measurement source | Not NULL; no default | Normalized measurement |
| `role` | `TEXT` | Measurement role or `calculated` | Not NULL; no default | Measurement/balance |
| `metric` | `TEXT` | Stable metric identifier | Not NULL; no default | Normalized metric |
| `value` | `REAL` | Finite accepted value | Not NULL; no default | Measurement or calculated balance |
| `unit` | `TEXT` | `W`, `kWh`, `V`, `A`, `%`, `Hz`, `ratio`, or `°C` | Not NULL; no default | Metric convention |
| `measured_at` | `TEXT` | Aware ISO-8601 measurement/calculation time | Not NULL; no default | Normalized model |
| `received_at` | `TEXT` | Aware ISO-8601 receipt/calculation time | Not NULL; no default | Normalized model |
| `quality` | `TEXT` | Accepted quality classification | Not NULL; no default | Validation/balance |
| `device_status` | `TEXT` | Snapshot status or `calculated` | Not NULL; no default | Snapshot/balance |

The unique constraint `(sample_id, source_id, role, metric)` prevents duplicate
cycle values. Missing and rejected values have no row. A real zero is stored
as `0.0`. Physical cumulative counters are converted from the normalized
in-memory Wh representation to kWh exactly once at persistence.

Indexes:

- `idx_measurements_metric_measured_at(metric, measured_at)` supports metric
  time ranges;
- `idx_measurements_source_metric_measured_at(source_id, metric, measured_at)`
  supports source-specific latest and range reads.

Query-plan validation and final index tuning remain block 10.7.

### `source_selection_events`

One row records each Phase 09 metric decision per collector cycle.

| Column | Type | Meaning | NULL/default | Origin and migration behavior |
| --- | --- | --- | --- | --- |
| `id` | `INTEGER` | Row identifier | Primary key; generated | SQLite |
| `sample_id` | `INTEGER` | Parent collector cycle | Not NULL; no default | `samples.id`; cascade delete |
| `selected_at` | `TEXT` | Aware ISO-8601 selection time | Not NULL; no default | Source selector |
| `metric` | `TEXT` | Requested metric | Not NULL; no default | Source selector |
| `selected_source_id` | `TEXT` | Selected source | Nullable for unavailable decision | Source selector |
| `selected_source_role` | `TEXT` | Selected role | Nullable for unavailable decision | Source selector |
| `selected_quality` | `TEXT` | Selected or unavailable quality | Not NULL; no default | Source selector |
| `fallback_used` | `INTEGER` | Boolean 0/1 fallback decision | Not NULL; no default | Source selector |
| `selection_reason` | `TEXT` | Stable decision reason | Not NULL; no default | Source selector |
| `rejected_candidates_json` | `TEXT` | Bounded rejected-candidate array | Not NULL; default `[]`; maximum 16,384 characters | Sanitized source metadata |

The unique constraint `(sample_id, metric)` prevents duplicate decisions.
`idx_source_selection_events_metric_selected_at(metric, selected_at)` supports
metric history. Oversized candidate lists are truncated at whole-candidate
boundaries; credentials and raw device responses are never included.

## Public migration interfaces

`solarinspector_core.persistence.migrations` provides:

- `get_current_version(connection)`;
- `get_target_version()`;
- `plan_migrations(current_version)`;
- `apply_migrations(connection, application_version, applied_at=None)`;
- `verify_schema(connection)`.

All functions operate on a caller-owned SQLite connection. Planning and
verification are read-only. Application writes are explicit and transaction
owned by `apply_migrations`.

## Verification contract

Target version 2 verification requires:

- an exact, contiguous, known migration history with matching descriptions
  and SHA-256 checksums;
- all five Phase 09 domain tables, both migration audit tables, and both
  version-2 time-series tables;
- the columns required by current persistence and query contracts;
- all six characterized domain indexes, the migration-finding index, and all
  three version-2 time-series indexes;
- `sample_id -> samples(id) ON DELETE CASCADE` on phase, grid-meter, and
  energy-balance detail tables.

Verification intentionally accepts extra legacy columns because version 1
preserves them and records a finding instead of silently discarding them.

## Architecture alternatives

### Selected: compatibility parent plus versioned additive transition

This minimizes migration risk and preserves all existing API, dashboard, CSV,
energy-integration, and deletion behavior.

### Rejected for now: immediately replace the wide table

Replacing `samples` would combine schema versioning, data conversion, query
rewrites, exports, and retention in one irreversible step. Units and source
identity are not reliable for every historical wide column.

### Rejected: keep presence-based `ALTER TABLE` as the version model

Column presence cannot distinguish supported intermediate schemas, detect a
newer application schema, verify checksums, or prove that a multi-step
migration committed completely.

## Known limitations after block 10.6

- Empty-database initialization still uses the established `Database` path.
- `Database.initialize()` remains unchanged and does not use the version
  ledger.
- Version-2 writes activate only when the migrated tables exist; startup
  migration is assigned to a later block.
- Historical query APIs, backup, dry run, CLI, startup integration, and
  retention remain assigned to later blocks.
